## Primary post (recommended)

Most teams don’t struggle to store data.
They struggle to **understand how it connects**.

I built **GraphLoom** — a web app that helps organizations weave knowledge graphs from the databases they already trust.

In this short demo (retail sample warehouse), you can see:

🔹 Sign in with a personal account or SSO  
🔹 Spin up multiple projects  
🔹 Connect sources (CSV today; Postgres / MySQL / MSSQL / MongoDB connectors ready in the UI)  
🔹 Auto-suggest joins from real value overlap  
   e.g. if `sales_fact.product_id` values also appear in `product_master.product_id` → confirm the link  
🔹 Upload SQL or define relationships manually  
🔹 Paste a plain-English ontology / data dictionary  
🔹 Auto-generate a living data dictionary  
🔹 Explore the resulting knowledge graph

The seed project includes product, consumer, date, promotion, store, sales, and inventory masters — so the graph isn’t empty on day one.

If you’re working on data products, semantic layers, or knowledge graphs for internal systems, I’d love your feedback.

🛠️ PR / build notes in the repo README

## Shorter alternative (if you prefer punchier)

What if your warehouse could explain its own relationships?

**GraphLoom** turns internal databases into knowledge graphs:

• Connect CSV / SQL sources  
• Suggest joins from overlapping values  
• Confirm links, upload SQL, or add ontology in plain English  
• Keep an auto-built data dictionary  
• Explore multi-project graphs
